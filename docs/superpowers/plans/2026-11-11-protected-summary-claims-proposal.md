# 보호 사실을 고정하는 요약 생성 보완안

상태: 사용자가 2026-11-11에 보호 사실 고정·AI 선택/구성 방향을 선택했다. 로컬 구현의 정기 실행 반영은 main 병합 후 적용된다. 코드 검증은 저장소 fixture로 재현하며 실제 주차의 생성·게시 이력은 별도 운영 감사 범위다.

2026-11-11 요약본은 세 프로젝트 생성과 수동 복구 게시까지 완료했지만 사실 검증은 실패했다.
기존 증거의 오류는 수치 대상 5건, 판정 문맥 10건, 표시 없는 판정어 2건이다.
형식 검사의 3건은 정식 알고리즘명과 명시적인 제품명을 내부 식별자로 잡은 오탐이다.
기존 실패 증거·보고서·게시 영수증을 통과 상태로 고치지 않는다.

## 현재 수정 범위

- 정식 알고리즘과 명시적인 제품명·발주 코드의 형식 검사 오탐을 좁은 토큰 경계에서 교정한다.
- `실측`도 측정 근거로 인식해 기존 괄호 구절 추출기가 LAN 응답의 `2~9초`를 대상·범위·단위와 묶도록 한다.
- 판정이 없는 독립 측정 근거를 선택할 때 같은 커밋의 이후 검증 메모까지 선택했다고 보지 않는다.
  같은 행의 판정, 판정이 있는 조상, 실제 하위 판정은 계속 결속한다.
- 이 수정만으로 기존 요약본 전체가 검증을 통과한다고 주장하지 않는다.

## 남은 원인

팀 요약은 업무 주제로 재구성하도록 안내하지만 판정 검증은 원문의 부모·자식 문맥까지 그대로 요구한다.
코드가 보류 문구에 기준일을 넣는 변환도 원문 행 대조와 충돌한다.
한편 AI가 AP 옆이라는 조건, 대역폭만 바꿨다는 조건, 시험 결과를 생략하거나 보호 판정어를 직접 재작성한 사례는 실제 차단 대상이다.
판정어 예외나 문자열 유사도 허용으로 이 차이를 덮지 않는다.

## 권장 변경

```text
sealed snapshot -> owned claims -> AI selection/structure
                                      |
                                      v
                              code-rendered facts
                                      |
                                      v
                              existing validation
```

1. 수치·판정·상태 문장을 원문 위치와 대상·조건·부정·결과에 결속한 전체 근거로 만든다.
   외부 부모가 의미를 결정하면 부모 근거를 함께 포함하거나 독립 선택에서 제외한다.
2. 보호 사실은 AI가 식별자로 선택하고 코드가 표시 문구를 조립한다.
   AI는 묶음·고정 주제·강조만 선택하며 선택하지 않은 설명이나 보호 사실을 자유 문장으로 추가하지 못하게 한다.
3. 보류 기준일은 현재 상태를 확인한 근거가 있을 때만 표시한다.
   과거 Notion 메모에 회의 날짜를 붙여 최신 상태가 확인된 것으로 만들지 않는다.
4. 잘못된 AI 선택은 명시적인 실패 또는 원문 근거로 조립한 요약 대체 결과로 남긴다.
   추가 AI 재호출이나 기존 실패 run의 증거 재작성으로 복구하지 않는다.

## 코드 완료 기준

- 저장소 fixture로 새 catalog/run을 만들고 생성·재검증·publish proof에서 동일한 근거 결속을 확인한다.
- 대상·조건·단위·값·부정·판정을 바꾼 반례와 중복·프로젝트 이동·증거 변조는 계속 실패해야 한다.
- 현재 상태 근거가 없는 NXP 문의 보류는 검증된 현재 상태로 표시하지 않는다.
- 모의 서버에서 게시 전 승인·원격 대조·다른 팀원 내용 보존과 기존 산출물 보존 경계를 검증한다.
- 전체 테스트의 실행·통과·실패·skip 수를 기록한다.

실제 수집 자료의 재생·AI 호출·복구 게시 확인은 운영자가 별도 감사 증거로 확인한다.
이를 저장소 회귀 테스트가 실제 서버의 과거 이력을 입증한 것으로 표시하지 않는다.

기존 자유 요약 run은 당시 프로필로 읽으며 새 실행에만 선택형 프로필을 적용한다.
