# 원문 선택 기반 주간보고 설계

사용자는 2026-09-09 대화에서 원문 문장 ID 선택, 결정적 렌더링, 검증된 대체 보고 경로를 승인했다.

## 목적과 범위

자유 요약과 문자열 기반 사실 검증의 충돌을 줄인다. `AI_GENERATION_METHOD=source_selection`을 추가하고 기존 기본값 `freeform`은 비교·호환 경로로 유지한다. 실제 cron 교체와 Redmine 게시는 구현 검증 후 별도 운영 단계다. 의존성 추가, 원격 쓰기, commit/push는 수행하지 않는다.

## 계약

1. 기존 schema v2에서 밑줄만 추가한 동일 사실이 차단되는 문제를 수정한다. GLIBC/wpa_supplicant의 명시적 버전은 수량과 구분하고 제품 결속 및 값 검증을 유지한다.
2. sealed snapshot에서 전체 원문 leaf bullet과 조상 문맥을 레코드로 만든다. 레코드는 원문 위치·카테고리·텍스트·fact/source 마커를 보존한다. 조상 조건을 생략하지 않는다.
3. AI 출력은 `{sections:[{id,groups:[{theme,items:[{id,highlight}]}]}]}` JSON이다. section 및 record ID는 원문에 존재해야 하며 카테고리 이동·중복·새 텍스트·알 수 없는 필드는 차단한다. theme은 고정 목록만 허용한다. 모든 내용 있는 section에서 적어도 하나의 항목을 선택한다.
4. 코드는 원문 문장과 조상 문맥으로 Markdown을 조립한다. AI는 수치·조건·상태·문장을 쓰거나 바꾸지 않는다. 사실 검증과 게시 시점 상태 검증은 계속 실행한다. 무조건적인 기준일 자동 부여는 하지 않는다.
5. `SOURCE_SELECTION_FALLBACK=1`(새 방식 기본값)이면 AI 호출 실패 또는 선택 JSON 오류에 한해 코드가 원문 순서로 section별 제한된 항목을 선택한다. 대체 보고서임을 본문과 run 증거에 표시한다. 검증 실패, 증거 손상, 설정 오류는 대체 경로로 우회하지 않는다. AI 추가 호출은 없다.
6. 새 방식에서는 open-status의 근거 부족·git 확인 실패·해결 가능성 경고도 차단한다. 문장 복사는 원문이 최신이라는 증명이 아니다.
7. source records, 선택 JSON, 선택 출처/실패 사유를 run에 보존한다. 선택 산출물과 원문 재구성 검사를 generate/revalidate/update 경계에 적용한다. 실패한 원본 AI 응답은 그대로 보존하고, 응답이 없으면 빈 원본과 명시적 실패 메타데이터를 남긴다.
8. `source_selection`은 `whole` 범위만 지원한다. 범위가 다르면 AI 호출 전에 실패한다. 기존 provider/호출시간/입력상한을 재사용한다.
9. generate 검증 실패 시 오류 종류·건수·run 경로를 cron stdout에 남긴다. update는 선행 generation 실패가 있으면 초안 부재보다 그 원인을 먼저 안내한다.

## 검증과 인수 기준

- 기존 전체 400 tests 기준선 유지.
- 장식 불변성, 버전/제품 변조 차단, 실제 09-09 표현 회귀 테스트.
- 선택 레코드·ID·필드·카테고리·중복·누락·부모 조건 보존 테스트.
- 정상 AI 선택 및 잘못된 JSON/호출 실패 대체본이 같은 검증/승격 경로를 거친다.
- 원문 조건·수치·상태가 변조된 working draft는 재검증/게시에서 거부한다.
- 과거 snapshot의 결정적 오프라인 재생으로 변경 전/후 진단 결과를 비교한다. 실제 AI 품질/운영 성공률을 오프라인 결과로 주장하지 않는다.

## 설계 판단

JSON이 사실 정확성을 보장하는 것이 아니다. 허용된 원문 전체를 코드가 선택해 출력한다는 계약이 문장 변조를 제거한다. 자유로운 압축은 감소하며 선택의 중요도는 여전히 AI 품질에 영향을 받는다. 기존 숫자 검증기는 비교 경로와 추가 방어로 유지한다.
