# 검증 실패 요약본 우선 게시

## 요청과 근거

사용자는 검증에 실패해도 원문 대신 요약본이 게시되기를 원한다.
2026-11-11 실행은 첫 프로젝트의 `verdict_context_mismatch`로
`AI_PART_VALIDATION`이 발생해 나머지 프로젝트를 생성하지 못했다.
완성된 요약본이 없어 `variant: "2", status: "rejected_published"`로 게시됐다.

## 동작

- 주간 pair의 팀 요약본은 프로젝트의 사실·출처 검증 오류가 있어도 다음 프로젝트를 생성한다.
- 합친 요약본은 기존 최종 검증을 실행하고, 실패하면 실패 상태와 검증 기록 및 거부 보고서를 보존한다.
- `publish auto`는 정상 요약본, 검증 실패 요약본, 정상 depth2/depth3, 거부 depth2/depth3 순서로 선택한다.
- 실패 요약본은 기존 `검토 필요(자동)` 블록과 `rejected_published` 영수증으로 게시한다.
- AI 응답 없음, 잘못된 프로젝트·헤더·목록 구조, 증거 손상은 요약본 완성으로 취급하지 않는다.
- 이미 게시된 보고서 교체와 중복 게시 방지 영수증의 복구 승인은 기존대로 요구한다.

## 접근

기존 거부 보고서 게시 경로를 재사용한다. 팀 요약본에서만 내부 boolean을 켜서
프로젝트별 사실·출처 오류를 허용하되 최종 검증은 바꾸지 않는다.
검증을 생략하거나 실패 시 AI를 재호출하는 방식은 쓰지 않는다.

## 범위와 검증

일반 생성의 즉시 실패 동작, 명시적인 `publish 2|3`, 서버 쓰기 경계는 바꾸지 않는다.
Node 18+와 `node --test`를 사용하며 의존성을 추가하지 않는다.
외부 AI·Redmine·Slack 호출은 테스트 대역으로 한정한다.
실제 재게시·전송은 포함하지 않는다. 후속 사용자 승인에 따라 이 정책 변경과 실제 검증
오탐 교정을 별도 커밋·PR로 진행하고, #133은 후속 관리 이슈로 유지한다.
