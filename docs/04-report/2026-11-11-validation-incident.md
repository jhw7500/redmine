# 2026-11-11 주간보고 검증 실패 분석 (#152)

## 관측

11-11 정기 실행은 AI 응답을 받았지만 요약본 첫 PIM 부분에서
`AI_PART_VALIDATION`으로 중단됐다. 저장된 run state에는
`verdict_context_mismatch` 2건이 있다. depth2·depth3도 실패했고,
게시 영수증은 `variant: "2", status: "rejected_published"`를 기록했다.

근거는 운영 경로 `out/pairs/2026-11-11`의 sealed snapshot,
요약 run `814636c2-7562-4d5a-a01b-953406fe91be`의 `state.json`,
depth2 run `af29ad88-a19d-4129-a9ce-3de8b81e8993`의 `validation.001.json`이다.
이 파일은 당시 보존 증거의 관측을 기록하며 실제 AI·서버 재실행 결과는 아니다.

## 원인과 수정 범위

1. **명사형 실패 표현의 판정어 오분류.** 원문의 `실패 복원 실행기`에서 `실패`가
   `test_verdict`가 됐다. 판정 검증은 같은 행의 `E2E`까지 원문 행과 부모·자손에 결속하므로,
   AI가 두 문장을 별도 항목으로 나누자 두 근거 모두 거부됐다. 판정 검증의 대상·문맥
   결속을 완화하지 않고, 사고에서 확인한 구체적 도구 명칭의 추출 분류만 교정한다.
   `배포·백업·실패 복원 실행기`와 뒤에 조사 `와`가 붙은 형태에서만 `실패`를
   일반 보호 토큰으로 남긴다. 접두 열거와 실행기 단어 경계를 모두 확인한다.
   `실패 원인`, `실패 처리`, `통과 기준`, 일반 `실패 복원`은 실제 결과를 주장할 수
   있으므로 판정어를 유지한다. 붙여 쓴 `실패복원`과 알 수 없는 활용도 같은 원칙이다.
   `실패입니다`, `실패임`, `실패였다`, `실패로 끝났다`, `실패 보고` 같은 실제 결과에서
   대상·조건을 바꾸는 것은 계속 거부한다. 모호한 명사 수식형에서도 대상·조건·부모를
   바꾸면 거부하며 warn/override로 이 검증을 우회할 수 없다. 일반 토큰도 값 변경을 허용하지 않는다.
2. **공유 단위가 붙은 숫자 목록의 겹침.** 원문 `40/80 MHz`에서는 ratio `40/80`이
   `80 MHz`와 겹쳐 뒤 후보를 버린다. 출력에서는 표식된 ratio를 제외한 다음 `80 MHz`를
   선택해 원문을 그대로 옮겨도 `unmarked_protected_fact`가 된다. 공유 단위까지 전체
   사실로 소유하도록 추출을 맞추고 새 단위 추가·숫자 변경·구간 침범의 차단을 유지한다.
3. **테스트 카운터의 열린 작업 오인.** `node --test` 검증 집계의 `todo 0.`이 쉼표로
   잘린 뒤 실제 TODO로 판정됐다. 명확한 테스트 결과 문맥의 해당 카운터 구간만 구분한다.
   독립 TODO·FIXME와 같은 줄의 별도 열린 작업은 계속 검사한다.

## 실제 확인이 필요한 상태

`NXP 문의 보류`에는 기준일이 없고 해당 run의 `openIssueChecks`도 비어 있다.
이 항목은 오탐으로 확정할 수 없다. 임의 날짜를 붙이거나 warn/override로 통과시키지 않고
`open_status_without_as_of` 및 `source_selection_status_unverified` 차단을 유지한다.
따라서 오탐을 고쳐도 이 입력의 전체 검증이 PASS가 된다고 주장하지 않는다.

## 검증 및 운영 경계

저장소의 짧은 비밀값 없는 회귀 입력으로 catalog·주석·확장·검증 경로와 위조 차단을
재현한다. 운영 snapshot 전체나 자격증명을 테스트에 복사하지 않는다. 정량 결과는 실제
실행 후 커밋과 PR의 Validation에 기록한다.

봉인된 기존 run의 catalog·원문·해시는 바꾸지 않는다. 사실 추출이 바뀐 새 동작은 새
catalog/run에 적용하며 기존 사고 run을 제자리에서 정상 상태로 바꾸지 않는다.
기존 catalog에 남은 `test_verdict`는 새 추출기가 그 표현을 명사형으로 분류하더라도
원래의 행·문맥 결속을 유지한다. 새 명사형 분류를 적용하려면 새 catalog가 필요하다.
실제 AI 재호출·위키 재게시·Slack 전송과 운영 코드 반영은 이 수정 검증에 포함하지 않는다.

검증 실패에도 전체 요약본을 만들고 우선 게시하는 정책은 #133의 별도 PR A다.
이 사고의 오탐 교정은 #152에서 다루며, #133의 과거 번호 주어 대조 검토를 종료하지 않는다.
